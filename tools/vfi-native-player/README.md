# vfi-player — 프레임 보간 5단계 네이티브 재생 실험 도구

[개발 계획](../../docs/research/vfi-dev-plan.md)의 5단계 도구입니다. 보간할 프레임을 앱이 직접 쥐는 재생 경로를 CView 앱 밖에서 검증합니다. 앱 코드와 앱 빌드는 바꾸지 않습니다. 결과는 [5단계 실측 보고서](../../docs/research/vfi-native-player.md)에 있습니다.

```
HLS·LL-HLS·MP4 ─▶ AVPlayer ─▶ AVPlayerItemVideoOutput(420v IOSurface, 앞당겨 받기)
                   │ 오디오는 AVPlayer가 그대로 낸다           │
                   │                                  장면 전환 감지(64×36 휘도 SAD + 32칸 히스토그램)
                   │                                          │
                   │                         VTLowLatencyFrameInterpolation(ANE, 한 번에 1건)
                   │                                          │
                   │                         정지 화소 보호(NV12 Y·CbCr), 마감 서킷브레이커
                   ▼                                          ▼
              AVPlayerItem 시계 ──────────▶ 원본·중간 프레임을 PTS 순서로 출력(null / 표시 레이어 / 창)
```

## 빌드·실행

macOS 26 이상과 Xcode가 필요합니다. VideoToolbox 세션은 샌드박스 안에서는 시작되지 않을 수 있으니 일반 터미널에서 실행합니다.

```sh
tools/vfi-native-player/build.sh                     # → <target>/vfi-native-player/vfi-player
vfi-player --help
vfi-player --file 영상.mp4 --seconds 60               # 창 없이 측정
vfi-player --chzzk popular --sink window              # 치지직 인기 공개 방송을 창에 띄워 보기(i: 보간 켜고 끄기, q: 끝)
tools/vfi-native-player/run.sh /tmp/vfi-runs          # 시나리오 전체(약 35분, long 절 제외)
```

- 출력 방식(`--sink`)
  - `null`(기본): 창이 없습니다. 출력 프레임을 표시 시각까지 붙잡았다가 놓아, 실제 출력 큐가 버퍼를 쥐는 시간을 흉내 냅니다.
  - `renderer`: 창이 없습니다. 창에 붙이지 않은 `AVSampleBufferDisplayLayer`의 렌더러에 `AVSampleBufferRenderSynchronizer`로 넣습니다. 끝날 때 렌더러 성능 지표를 남깁니다.
  - `window`: 창을 띄웁니다. 사용자가 직접 실행합니다. `i` 키로 보간을 켜고 끄며 비교하고, `q` 키로 끝냅니다.
- 소스: `--file`, `--url`(HLS·LL-HLS·MP4), `--chzzk <채널 id|popular>`.
  - 치지직은 로그인 없이 공개 방송만 봅니다. 성인·유료·암호화 방송은 건너뜁니다.
  - 재생 주소에 든 토큰은 화면에도 기록에도 남기지 않습니다.
- `--generate`로 시험 영상을 만듭니다. 흐르는 체크 무늬, 빠른 공, 고정 자막, 프레임마다 바뀌는 타이머가 들어 있고 8초마다 장면이 바뀝니다.
- `--probe-sizes`로 VT 저지연 보간이 실제로 도는 크기를 확인합니다. 세션 시작 뒤 처리 3회까지 해 봅니다.

## 설계

**앞당겨 받기**
- `copyPixelBufferForItemTime:`은 질의 시각 이하의 가장 늦은 프레임을 주고, 그 앞 프레임은 말없이 버립니다.
- 그래서 `hasNewPixelBufferForItemTime:`을 이분 탐색(0.4ms 정밀도)해 바로 다음 프레임만 받습니다.
- 앞당기는 거리 상한은 150ms(`--lookahead-ms`), 붙잡아 두는 미처리 프레임은 6장(`--max-ahead`)입니다.
- 받기 스레드는 실시간 정책(`THREAD_TIME_CONSTRAINT_POLICY`)으로 2ms마다 깨어납니다.

**마감**
- 중간 프레임의 마감은 `호스트 시각(중간 PTS) − 5ms`(`--lead-ms`)입니다. 아이템 시계의 현재 시각·속도로 계산하므로 1.03배 따라잡기에도 맞습니다.
- 마감을 넘긴 짝은 원본만 내보냅니다. 늦게 끝난 결과는 버립니다.
- 최근 처리 시간 p75 안에 끝낼 수 없는 짝은 처음부터 넣지 않습니다.
- VT에는 한 번에 1건만 넣습니다(1080p에서도 동시 처리 이득이 없었습니다).

**순서**
- 원본 n+1은 중간(n, n+1)이 끝나거나 포기될 때까지 붙잡습니다.
- 출력은 항상 PTS 순서입니다. 순서가 어긋나면 `order_violation`으로 셉니다(0이어야 합니다).

**세대 번호**
- 세대를 바꾸는 계기:
  - `outputSequenceWasFlushed:`
  - `AVPlayerItemTimeJumpedNotification`
  - 거꾸로 가는 PTS
  - 크기 변화
  - 프레임률 변화(최근 9개 간격의 최솟값이 25% 넘게 바뀐 상태가 3번 이어짐. 프레임이 빠지면 간격이 길어지기만 하므로 최솟값을 쓴다)
  - 재연결
- 세대가 바뀌면 다음을 합니다.
  - 미처리 프레임을 버립니다.
  - 보호 장치를 초기화합니다.
  - 브레이커 창을 비웁니다.
  - 출력을 비웁니다(flush).
  - 처리 중인 요청의 결과를 버립니다(`stale_dropped`).
- 세대 시작 뒤 2초는 준비 구간입니다. 보간은 하지만 비율과 브레이커 판단에서 뺍니다.

**VT 세션**
- 크기마다 따로 만듭니다. 시작하고 처리 3회로 확인한 뒤에 씁니다. 1440×810처럼 시작은 되지만 처리에서 실패하는 크기는 원본만 냅니다.
- VT에 넘기는 시각은 세대마다 앞 세대보다 1초 뒤로 옮겨 단조 증가를 지킵니다(간격은 그대로).

**보호 장치**
- `tools/frame-interp-lab/bench.m`의 cut·static을 NV12에 맞게 옮겼습니다. 문턱은 같습니다.
- 썸네일·히스토그램은 비디오 범위(16~235)를 전체 범위로 펴서 계산합니다.
- 정지 화소는 Y를 두 원본 평균으로 바꿉니다. CbCr은 2×2 화소가 모두 정지일 때만 평균으로 바꿉니다.

**브레이커(v3)**
- 연구 계획 1단계의 v2는 '도착 + B' 마감 모델이라, 처리 시간의 흔들림이 곧 늦음이었습니다.
- 여기서는 앞당겨 받기 덕분에 마감까지 여유가 있습니다(720p60 중앙값 약 100ms). 그래서 규칙을 다음처럼 바꿨습니다.
  - 창의 10% 이상이 늦음이면 엽니다. 단, 요청 자체가 느렸던 늦음(처리 시간 > 0.75·입력 간격)만 셉니다. 앞 요청이 느려 대기열에서 늦게 출발한 짝까지 세면, 쉰 뒤 첫 요청이 느린 ANE 특성과 맞물려 '열림 → 쉼 → 느린 첫 요청 → 늦음 → 다시 열림'이 반복됐습니다(치지직 4분에 21번).
  - 창 평균 처리 시간이 입력 간격을 넘으면 엽니다(1080p처럼 따라가지 못하는 경우).
  - 한 건 규칙은 없습니다. ANE가 가끔 200~300ms 멈춰도 그동안은 어차피 1건만 처리 중이라 끌 이득이 없습니다. v2의 '한 건 > 2·B'는 마감 안에 끝난 72ms 한 건에도 열려 1초씩 보간을 쉬었습니다.
  - 반쯤 열림: 열린 동안 시험 요청(결과는 내보내지 않음, ANE 사용률 20% 이하)으로 ANE를 깨워 둡니다. 오래 쉬면 다시 켠 직후 느려져 곧 다시 열리는 악순환이 있었습니다. 시험 요청은 낮은 클럭 상태라 연속 처리 속도를 보여 주지 못하므로, 아예 못 따라가는 경우(시험 중앙값 > 2·입력 간격, 1080p)만 열린 기간을 1초씩 늘리고, 나머지는 기간이 끝나면 닫고 실제로 다시 시도합니다. 닫은 직후 10건은 창에 넣지 않습니다.
- 열린 기간은 1·2·4·8·16·30초로 늘어나고, 10초 동안 정상이면 1초로 돌아갑니다(v2는 8초까지). 다시 시도할 때마다 보간이 켜졌다 꺼지므로, 계속 실패하면 오래 쉬게 했습니다.
- v2는 `--breaker v2`로 고릅니다.

## 측정 항목(`--json`, `--csv`)

- `counts`
  - `eligible`: 비율 계산에 넣은 짝(장면 전환·간격 이상·준비 구간·끊김 제외)
  - `on_time`
  - `late`: 마감 초과·포기
  - `late_start`: 처리를 시작할 수 없을 만큼 늦음
  - `bypass`: 브레이커가 열려 건너뜀
  - `cuts`, `gaps`
  - `stale_dropped`, `order_violation`
  - `orig_late`: 원본이 표시 시각을 넘겨 나감
- `ms`
  - `proc`: VT 처리
  - `guard`: 보호 장치 갱신
  - `composite`: 정지 화소 합성
  - `lookahead`: 받을 때 표시까지 남은 시간
  - `slack_at_ready`: 준비된 뒤 마감까지 여유
- `latency_s`: `현재 시각 − AVPlayerItem.currentDate`(PDT 기준)입니다. 앱의 `perf-collector.js`(`Date.now() − hls.playingDate`)와 같은 기준입니다.
- `criteria`: 연구 계획 2장 기준의 자동 판정입니다.
  - C2: 제때 ≥ 95%, 늦음 ≤ 1%, 전환 ≤ 분당 60회
  - C8: 10분 이상일 때 메모리 증가 ≤ 50MB, 지연이 늘지 않음
  - 출력 순서·이전 결과 혼입 없음

## 이 도구로 재지 못하는 것

- **A/V 동기(±20ms)와 실제 화면 표시 시각.** 창 없는 모드에서는 영상 시계가 정의상 아이템 시계와 같습니다. 창 모드에서 눈으로 확인하거나, `CAMetalLayer` 표시 시각 기록을 더해야 합니다.
- **웹 대비 지연(C7).** 같은 채널을 CView로 동시에 틀어 놓고 `latency_s`를 앱의 지연 표시와 비교해야 합니다.
- **화질.** 3단계 도구(`tools/frame-interp-lab`)에서 합성 장면으로 잽니다.
