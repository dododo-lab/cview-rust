## 디버그 로그
설정 → 성능·진단 → **디버그 로그**(기본 꺼짐) 또는 `CVIEW_DEBUG_LOG=1`. 같은 곳의 **로그 폴더 열기** 버튼.

- 위치: macOS `~/Library/Application Support/app.cview.rust/logs/debug.jsonl`, Windows `%APPDATA%\app.cview.rust\logs\debug.jsonl`
- 형식: JSON 한 줄씩, 10MB × 5개 순환. 쿠키·토큰·인증 헤더·쿼리 문자열은 남기지 않는다(경로만).
- 꺼져 있으면: 기록 스레드·표본 스레드·요청 관찰자·화면 수집기 모두 멈춤(호출 지점은 원자 플래그 하나만 확인).
- 남기는 것
  - `startup.*` — 프로세스 시작 → setup 시작·서비스 준비·setup 끝(ms)
  - `ui.startup` — 페이지 로드 → 조작 가능, DOMContentLoaded
  - `ui.first_live_frame` — 재생 요청 → 첫 라이브 프레임
  - `process` (10초) — 앱 + WebKit/WebView2 도우미별 CPU·RSS, 채팅 메시지·묶음/초, 화면 이벤트/초
  - `net.request` — API 시도마다 메서드·경로·상태·실패 종류(timeout/connection_lost/…)·걸린 시간·크기·캐시 적중
  - `ui.frames` (10초) — 10초 중 1초 표본의 프레임 p50/p95/최대·50ms 넘은 프레임, DOM 요소 수, JS 힙, IPC 이벤트, 채팅 렌더 줄
  - `ui.player` (10초) — 재생 중인 영상마다(시청 화면·멀티 패인) 해상도·화질 단계·버퍼·라이브 지연·떨어진 프레임·버퍼링 횟수/시간
  - `player.event` — 플레이어 오류·치명 오류·재생 상태·화질 목록·고정 화질
  - `chat.state` — 채팅 연결 상태 변화
- 분석:
  ```
  python3 perf/tools/analyze-log.py "$HOME/Library/Application Support/app.cview.rust/logs/debug.jsonl" \
      [--since 2026-10-20T12:04:25] [--until 2026-10-20T12:05:25] [--label 이름]
  ```
  시작·프로세스·네트워크(분당·경로·실패)·화면 프레임(화면별)·플레이어(위치별)·채팅 상태를 마크다운 표로 낸다.

## 개선하지 않은 것과 이유
- **팔로잉 목록 8쪽 폴링(분당 8건, 약 290KB)** — 방송 시작 알림이 전체 팔로잉의 방송 상태를 알아야 해서 필요하다. 지금 쓰는 팔로잉 API 는 방송 중인 채널만 따로 주지 않아 전체 목록을 쪽 넘김으로 받는다.
- **멀티라이브 4패인 GPU** — 영상 4개 디코딩·합성 비용이라 앱 코드로 줄일 몫이 작다. 패인마다 엔진 화질 상한(`max_height_cap`)이 이미 있다.
- **스플래시 최소 0.4초** — 깜빡임 방지용 의도된 값.
- **10분 메모리 누수 확인·멀티채팅(g)** — 사용자 요청으로 측정 시간을 줄여 이번에도 재지 않았다.
