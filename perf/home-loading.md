# 홈 시작·썸네일 로딩 — 전후 측정 (2026-10-31)

사용자 요청: "앱 실행 시 홈 화면 썸네일 등 데이터 로딩 속도 최적화. 기타 앱 사용 중 썸네일 로딩 최적화".
이전 썸네일 캐시 작업(`perf/thumbnails.md`) 위에 쌓은 것이다.

## 바꾸기 전 — 시작 화면이 기다리던 것
앱을 켜면 홈이 그려지기까지 아래가 **차례로** 일어났다.

1. 웹뷰가 뜬 뒤 `auth_status` — 저장된 로그인이 있으면 서버 확인(`/service/v1/users/me`) 한 번을 기다린다.
2. 그다음에야 홈이 `following_lives` · `popular_lives(48)` 를 부른다.
3. 인기 라이브는 화면 페이지(30개)씩 받았다 → 48개를 채우려고 **30개 요청 → 다음 커서 요청**, 두 번을 차례로.
4. 데이터가 오면 그리고, 그때부터 썸네일을 받는다.

웹뷰가 뜨는 동안(Rust 쪽은 이미 준비됨) 네트워크는 아무 일도 하지 않았다.

다른 화면의 썸네일: 다시보기·클립 썸네일은 크기 단계 없이 **원본**(1280×720~1920×1080, 세로 클립은 1080×1920)을 받았다.
카드 칸은 다시보기 약 330×185, 클립 약 170×300 이다.

## 바꾼 것
| | 무엇 | 어디 |
|---|---|---|
| 1 | 인기 라이브를 **한 번에 50개**(치지직이 받는 최대, 51 이상은 400) 받는다. 화면 페이지(30개)는 그대로. | `all_broadcasts.rs` `FETCH_SIZE` |
| 2 | **시작 미리 받기** — Rust 준비가 끝나면 곧바로 인기 라이브 첫 묶음을, 로그인 복원 직후 팔로잉 라이브를 받기 시작한다. 홈·사이드바 호출은 진행 중인 로드에 붙는다(새 요청 없음). | `lib.rs` `prefetch_popular` · `prefetch_following` |
| 3 | 시작 때 계정은 **서버 확인 없이** 저장된 로그인 복원 결과만 본다(`auth_status { quick: true }`). 닉네임·만료 판정은 홈을 띄운 뒤의 일반 확인·`auth://changed` 가 채운다. 복원이 끝나기 전에 물으면 기다린다(최대 3초) — 로그인 사용자에게 손님 홈이 먼저 보이던 경우도 막는다. | `commands/auth.rs` · `app.js` |
| 4 | 다시보기 썸네일 `?type=w640`(640×360), nng-phinf 클립 `?type=w640`(640×1138). video-phinf 클립은 가로·세로가 섞여 그대로(가로 원본을 줄이면 세로 칸에서 흐려진다). | `dom.js` `vod` · `clip` 종류 |
| 5 | 이미지 서버가 모르는 크기 단계면 404 → **원본 주소로 한 번 더** 받아 부른 주소로 저장한다(빈칸 대신). 아바타의 `f120_120_na` 도 같은 보호를 받는다. | `image_service.rs` `without_size_param` |
| 6 | 홈 히어로 큰 그림은 `loading="lazy"` 를 빼고 `fetchpriority="high"`. 자동 넘김 다음 장의 큰 그림을 1.2초 뒤 미리 받는다. | `home.js` |

## 측정 (이 클라우드 환경 → 치지직 실서버, 2026-10-31)
네트워크 지연은 한국 안의 사용자 Mac 보다 크다(요청 하나 약 0.9초). 그래서 **절대 시간보다 요청 수·비율**로 본다.

### 인기 라이브 48~50개 받기 — 7번 번갈아
| | 중앙값 | 각 회 (ms) |
|---|---:|---|
| 전: 30개 → 다음 커서 30개 (차례로 2번) | **1864ms** | 2159 · 2070 · 1864 · 1685 · 2085 · 1855 · 1682 |
| 후: 50개 한 번 | **951ms (−49%)** | 1514 · 936 · 1084 · 927 · 940 · 951 · 1043 |

홈이 그려지기 전 차례로 기다리는 왕복이 **3번 → 1번**이 된다(서버 계정 확인 1 + 인기 2 → 인기 1, 팔로잉은 같은 때 함께).
게다가 그 1번도 웹뷰가 뜨는 동안 이미 시작돼 있다(미리 받기).

### 썸네일 받는 양
| 그림 | 표본 | 전 | 후 | 줄어듦 |
|---|---:|---:|---:|---:|
| 다시보기(video-phinf, 인기 8채널 최근 3개씩) | 23장 | 3.43MB(장당 149KB) | 1.42MB(장당 62KB) | **−59%** |
| 클립(nng-phinf, 홈 추천 클립) | 19장 | 5.29MB(장당 279KB) | 2.08MB(장당 109KB) | **−61%** |

23장·19장 모두 `?type=w640` 이 200 으로 왔다(404 0장).

## 재지 못한 것
- 실제 앱(웹뷰)에서 "실행 → 홈 첫 화면 → 첫 화면 썸네일 다 보임" 시간. 숨긴 창은 그리기·타이머가 묶여 이 값을 바로 잴 수 없고,
  예전에 쓰던 디버그 평가 훅은 자동 모드에서 막혀 있다. 실제 앱에서 한 번 직접 확인이 필요하다.
- 로그인 상태의 `/users/me` 왕복 시간(이 환경엔 로그인이 없다). 비로그인 응답은 0.6~1.2초였다.
