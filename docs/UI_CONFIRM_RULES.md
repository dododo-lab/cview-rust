# 지우기·초기화 확인 규칙 (UI 리뷰 P3-4)

지우기·비우기·초기화 동작이 화면마다 다르게 물었다. 보관함의 최근 시청 기록은 두 번 누르기, 통계 › 데이터 관리의
같은 데이터는 모달, 설정 전체 초기화는 다른 두 번 누르기(타이머가 상태를 보지 않고 글자를 되돌림), 최근 검색어 모두 지우기는
묻지 않았다. 이 문서는 어떤 동작을 어떻게 물을지 정하고, 코드는 `app-ui/js/confirm.js` 한 곳에서 그 방식을 제공한다.

## 규칙

방식은 **무엇을 잃는지**와 **앱 안에서 되돌릴 수 있는지**로 고른다. 묻는 단계가 많을수록 실수는 줄지만 자주 쓰는 동작이
번거로워지므로, 잃는 것이 클수록 무거운 방식을 쓴다.

| 방식 | 언제 | 이유 | 코드 |
| --- | --- | --- | --- |
| 1. 확인 없음 | 다시 받아 오는 캐시, 화면에만 있는 것, 한 번 더 누르면 돌아오는 토글, 손으로 바로 다시 넣는 한 항목 | 잃는 것이 없거나 바로 되돌릴 수 있다. 물으면 확인 단계가 습관이 되어 정작 위험한 곳에서도 그냥 누르게 된다 | — |
| 2. 되돌리기 토스트 | 사용자가 만든 **한 항목**(북마크·멀티라이브 프리셋) | 한 항목을 지울 때마다 묻는 것은 번거롭다. 바로 숨기고 5초 동안 '되돌리기'를 준 뒤 실제로 지운다 | `deferDelete` |
| 3. 두 번 누르기 | 되돌릴 수 없지만 가볍고 **쓰다 보면 다시 쌓이는 목록 전체**(최근 검색어, 다운로드 기록 — 파일은 남음), 다시 입력하면 되는 자격 증명 | 한 번 실수로 누르는 것만 막으면 충분하다. 모달처럼 화면을 가리지 않는다 | `armConfirm` |
| 4. 확인 모달 | 앱 저장소(시청 기록 DB·설정 파일)를 **통째로** 바꾸고 앱 안에서 되돌릴 수 없는 것 | 무엇이 지워지고 무엇이 남는지, 복구 길이 무엇인지 읽고 결정해야 한다. 지우기 전 백업(내보내기)을 같은 자리에서 고를 수 있다 | `confirmDialog` |

덧붙임:

- **같은 데이터는 어디서 지우든 같은 방식**으로 묻는다. 최근 시청 목록은 보관함과 통계 › 데이터 관리 두 곳에서 지울 수 있는데,
  둘 다 같은 IPC(`clear_all_last_watched`)를 부르므로 둘 다 모달(백업 제안)로 묻는다.
- 목록 **한 항목**은 방식 1 또는 2, 목록 **전체**는 적어도 방식 3이다.
- 모달을 여는 단추는 글자 끝에 `…`를 붙이고 `aria-haspopup="dialog"`를 단다(macOS 관례: 더 물어볼 것이 있다는 표시).

### 설정 전체 초기화를 모달로 둔 이유

'다시 쌓이는 가벼운 목록'이 아니다. 열 개 설정 영역(재생·일반·화면·채팅·멀티채팅·단축키·네트워크·멀티라이브·채널 알림·동기화)이 한꺼번에
기본값으로 돌아가고, 그 안에는 손으로 다시 만들기 번거로운 금지어·차단 목록과 바꾼 단축키가 들어 있다. 앱 안의 되돌리기도 없다.
두 번 누르기로는 '로그인·시청 기록은 그대로'라는 범위와 '내보낸 파일을 가져오면 되돌릴 수 있다'는 복구 길을 보일 수 없다.
그래서 모달로 범위·남는 것·복구를 보이고, '초기화 전에 지금 설정을 내보내기'를 기본으로 켠다. 내보내기에 실패하면 초기화하지 않는다
(통계 정리의 '백업에 실패하면 지우지 않습니다'와 같은 약속).

### 보관함 › 최근 시청 기록 지우기를 모달로 바꾼 이유

이 목록은 다시 쌓이기는 하지만 시청 기록 저장소(DB)에 있고, 같은 동작이 통계 › 데이터 관리에서는 이미 모달 + 백업으로 묻고 있었다.
한쪽만 가볍게 두면 같은 데이터가 들어가는 곳에 따라 다르게 지워진다. 백업 상자를 끄면 예전처럼 두 번(열기·지우기)으로 끝난다.

## 방식별 동작

### 두 번 누르기 (`armConfirm(btn, { armedLabel, what, ms })`)

- 첫 누름: 단추 글자가 `한 번 더 누르면 지웁니다`(목록 전체면 `한 번 더 누르면 모두 지웁니다`)로 바뀌고 `data-armed="1"`이 붙는다.
  색은 `--error`, 안쪽 테두리 1px — 움직임(애니메이션)은 없다.
- 화면 낭독기: 단추 글자만 바뀌면 VoiceOver 가 읽지 않으므로, 공용 알림 자리(`#confirm-live`, `aria-live="assertive"`)에
  `최근 검색어 — 3초 안에 한 번 더 누르면 모두 지웁니다. Esc 로 취소합니다.`를 넣는다. `aria-label`이 있는 단추는 그것도 바꾼다.
- **3초** 안에 다시 누르면 확인. 첫 누름 뒤 **0.4초** 안에 온 누름(더블클릭·연타)은 무시하고, 누르고 있는 Enter·Space 의 반복 입력도 막는다.
- 풀리는 때: 3초가 지남, Esc(초점이 어디에 있든), 단추 밖을 누름, 초점이 단추를 떠남(Tab). 풀리면 글자·이름·알림을 되돌린다.
  WKWebView 는 누른 단추에 초점을 주지 않으므로 초점 이탈만으로는 부족해 바깥 누름(`pointerdown`)도 본다.
- 듣는 이벤트(문서 `keydown`·`pointerdown`, 단추 `focusout`)와 타이머는 무장한 동안에만 걸고 풀 때 모두 뗀다.
  목록을 다시 그려 단추가 바뀌면 무장도 사라진다(안전한 쪽).

### 확인 모달 (`confirmDialog({ title, facts, check, confirmLabel, className })`)

- `role="alertdialog"`, `aria-modal="true"`, 제목·설명을 `aria-labelledby`·`aria-describedby`로 잇는다.
- 내용은 `지울 대상 / 영향 / 복구`(설정 초기화는 `바뀌는 것 / 그대로 / 복구`) 세 줄.
- 백업·내보내기 상자는 기본으로 켠다. 그 단계가 실패하면 지우지 않는다.
- 처음 초점은 '취소'(Enter 한 번으로 지워지지 않게). Esc·바깥 클릭·취소는 아무것도 바꾸지 않는다.
- `a11y.js trapFocus`로 초점을 가두고, 닫히면 연 단추로 초점을 돌려준다.

### 되돌리기 토스트 (`deferDelete({ message, hide, restore, commit })`)

- 바로 숨기고 '되돌리기' 토스트를 5초 띄운 뒤(남은 시간 막대) 5.2초에 실제로 지운다.
- 숨긴 동안 목록을 다시 그려도 다시 나타나지 않게 지우는 중인 id 를 따로 기억한다.
- 되돌리거나 지우기가 실패하면 다시 보인다(실패는 오류 토스트).
- 키보드로 지웠으면 초점을 다음 항목(없으면 앞 항목)이나 시트 안으로 옮긴다.

범위 밖(지우기가 아니거나 따로 볼 것):

- 로그아웃 — 다시 로그인하면 된다. 지우기 규칙에 넣지 않았다.
- 팔로우 끊기(`chat-user-pop.js`) — 토글이지만 치지직 쪽 팔로우 시작일이 새로 매겨질 수 있다. 확인이 필요한지는 따로 판단한다.
- 설정 가져오기 — 덮어쓰기지만 사용자가 JSON 을 붙여 넣고 직접 제출하는 동작이라 이번 규칙에서 다루지 않았다.
- 멀티라이브 채널 닫기 — 데이터가 아니라 화면 구성.

## 검사

`tools/ui-regression/confirm-rule.mjs` — 모의 IPC 호출 기록으로 다음을 본다(실제 데이터는 건드리지 않는다).

- 두 번 누르기: 첫 누름은 안 지움, 더블클릭·누르고 있는 Enter 는 확인이 아님, 두 번째에 지움, 3초·Esc·바깥 누름·Tab 으로 풀림, 낭독기 알림.
- 모달: 취소·Esc·바깥은 안 지움, 초점이 '취소'에서 시작·안에 갇힘·닫으면 돌아옴, 백업(내보내기) 뒤 지움, 그 단계 실패면 안 지움.
- 되돌리기 토스트: 바로 숨김, 되돌리면 다시 보임, 시간이 지나면 지움.
- 화면 코드에 따로 짠 두 번 누르기(`data-armed`)가 남아 있지 않음.
